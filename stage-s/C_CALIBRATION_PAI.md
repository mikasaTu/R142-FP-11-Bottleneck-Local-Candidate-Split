# Stage-S C Step-0 pooled-only calibration

This is the non-submitting PAI hand-off for the Stage-S C qualification
screen. It evaluates the maintained Stage-R `Task64Environment` and policy
against four exact, real `pi05_libero` under-trained checkpoints. Every
setting is labelled `WEAK_SUBSTRATE`; this is a substrate qualification
measurement, not a claim about a production policy.

## Frozen calibration

The pinned runtime is
`scripts/stage_s_libero_calibrate.py` from the independent C checkout at
`/mnt/cpfs/zbl-cpfs-new/USERS/leon/code/r142-stage-s-c-runtime-20260903`,
commit `7575da585be31eb369a604d90048b338bbbf2c92`.

The four settings are exactly `step_1000`, `step_3000`, `step_6000`, and
`step_10000`, corresponding to native full-state checkpoints from the C
training run named by the accepted training lineage. The frozen grid is
tasks `[0, 3, 6, 9]`, initial states `0..7`, eight candidates, and eight
torchrun ranks, for 256 trials per setting. No interpolation, artificial
degradation, synthetic fallback, or checkpoint substitution is permitted.

Each result row may contain only:

```text
setting, successes, total, pooled_success
```

The completion marker binds all four setting labels to `WEAK_SUBSTRATE`.
S2--S5, genealogy, trajectories, actions, poses, divergence, and other
trial-level fields are forbidden from calibration output.

## Input gate

Before simulator import, the launcher requires the main-thread-owned,
atomically published
`/mnt/cpfs/zbl-cpfs-new/USERS/leon/logs/r142_fp11_stage_s/c_status/ACCEPTED_C_TRAINING.json`
with schema `r142-stage-s-c-training-acceptance-v1`. Its
`accepted_run_id` and terminal `job_id` are read dynamically, so a later
blackout/resume lineage is not confused with a stopped run. The launcher
then requires:

- `status=ACCEPTED`, `label=WEAK_SUBSTRATE`, and
  `pai_terminal_status=Succeeded`;
- exact pinned `source` commits for Stage-S, QPILOTS, OpenPI, and LIBERO;
- `checkpoint_hashes` containing exactly these relative-path to SHA-256
  entries: `1000/model.safetensors`, `3000/model.safetensors`,
  `6000/model.safetensors`, and `10000/model.safetensors`;
- each accepted model hash must match the corresponding non-symlink file in
  the common checkpoint root. This is in addition to checking the complete
  checkpoint and log manifests below.

- `CKPT/leon/r142_stage_s_c/COMPLETED_C_TRAINING.json`;
- `CKPT/leon/r142_stage_s_c/SHA256SUMS` passing from that checkpoint root;
- the accepted run's log-root `SHA256SUMS` passing;
- the accepted run's `c_status/COMPLETED_C_PIPELINE.json` binding the run id
  and completion marker;
- complete `model.safetensors`, `optimizer.pt`, `metadata.pt`, and all eight
  RNG sidecars at steps 1000/3000/6000/10000;
- the pinned runtime's `audit_c_checkpoint_schedule` returning valid with
  `WEAK_SUBSTRATE` and full reference step 30000.

The acceptance manifest's source commits, four model hashes, and
checkpoint/log manifest digests must match the pinned source trees and common
completion marker. The C
training outputs are read-only inputs. The run-scoped LIBERO config is
copied byte-for-byte from the pinned LIBERO checkout into the calibration
artifact directory and must match on every resumed incarnation.

## Resource and resume contract

The manifest selects the registered robot-idle graphics alias
`idle-a800-robot-stage-s-graphics-8gpu` (`quota1ssrabud0bh`, `exp-robot`): one
worker, exactly eight A800 GPUs, 88 CPU cores, and 1525 GiB each for memory
and shared memory. Public `pod_env` is exactly
`NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics`; EGL variables are set
inside the workload. Provenance is pinned to carrier
`dlckjz66iwcv38gw`. The launcher is externalized at
`/mnt/cpfs/zbl-cpfs-new/USERS/leon/code/r142-stage-s-pai-20260902/`.

The payload never submits a PAI job. PAI `Sync`/`OnFailure` with a maximum of
50 restarts resumes the same run id and artifact directory. All rank markers
and SHA files are required before `COMPLETED_C_CALIBRATION.json` and
`C_SHA256SUMS` are published. The launcher exits closed during the Beijing
blackout windows `09:30--09:40` and `19:30--19:40`.

blocked until the main thread publishes an accepted terminal training
lineage and all checkpoint/SHA gates pass.
